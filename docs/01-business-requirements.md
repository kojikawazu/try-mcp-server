## 背景・目的

**MCP（Model Context Protocol）を「作る側」と「使う側」の両方から、手を動かして理解する**ためのお試し用リポジトリ。

| 側 | やること | 置き場所 |
|---|---|---|
| 作る | MCP サーバーを TypeScript/Node.js で自作し、伝送方式・ツール・リソース・プロンプトなどを小さな単位で試す | `experiments/`（1 実験 1 フォルダ） |
| 使う | 既製の MCP サーバーを登録し、**複数のクライアント（Claude Code / GitHub Copilot CLI）から同じ設定で**動かす | `.mcp.json` |

このリポジトリで確かめたいのは「自分の環境で MCP が動くか」ではなく、**「リポジトリの設定だけで、どのクライアントからも同じものを再現できるか」**である（判断基準は「主要な決定事項」を参照）。

## スコープ

- MCP サーバーの自作実験（`experiments/`）
- 既製の MCP サーバーの登録と、Claude Code / Copilot CLI の両方からの動作確認（`.mcp.json`）
- クライアントごとの読まれ方・承認・認証・優先順位の違いの記録（README・`docs/lessons-learned.md`）

### スコープ外（将来拡張）

- 本番運用を前提にしたサーバーの開発・公開
- 認証情報（API トークン・鍵）をリポジトリで管理する接続方式。リモートのサーバーは各クライアントの OAuth に任せる
- `.mcp.json` を読まないクライアント（Codex など）への設定の展開。必要になった時点で別に検討する

## 主要な決定事項

### 既に使える MCP でも `.mcp.json` に載せる

**claude.ai のコネクタやユーザー設定で既に使えるかどうかは、このリポジトリに入れるかの判断材料にしない。** 判断の基準は「リポジトリの設定だけで、どのクライアントからも再現できるか」である。

理由: claude.ai のコネクタ・ユーザー設定（`~/.claude.json` など）は、このリポジトリの目的に対して次の点で代わりにならない。

| 観点 | claude.ai のコネクタ・ユーザー設定 | `.mcp.json` |
|---|---|---|
| 使えるクライアント | Claude 系のみ（コネクタ）／そのクライアントのみ（ユーザー設定） | Claude Code と Copilot CLI が同じファイルを読む |
| 版・接続先 | 管理側や `@latest` に任せる（例: コネクタが廃止予定の V1 のまま） | リポジトリで固定し、差分として残る |
| 他の人・別の環境 | 配れない | clone すれば同じ設定になる |
| 見えるもの | 「動いた」という結果だけ | クライアントごとの承認・認証・優先順位の違い |

実際に、Playwright MCP（#4）では「Claude Code は `.mcp.json` を承認するまでユーザー設定を使う」こと、Atlassian MCP（#6）では「Claude Code はコネクタと `.mcp.json` を URL で同一判定する」「Copilot CLI はアカウントのポリシーで外部 MCP を止める」ことが分かった。いずれも、既存のコネクタやユーザー設定で済ませていたら見えなかった。

### 認証情報はリポジトリに書かない

リモートの MCP サーバーは OAuth で接続し、`.mcp.json` には URL だけを書く。トークンは各クライアントが利用者ごとに保持する。
